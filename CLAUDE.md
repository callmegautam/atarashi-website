# atarashi-website

Marketing site, documentation and blueprint registry for atarashi, the CLI in
`../atarashi`.

## Rules

These are standing rules, not suggestions. They apply to every file and every
commit in this repo.

1. **No em dashes.** Not in code, comments, docs, page content, or commit
   messages. Use a comma, a colon, or a full stop instead. The one exception is
   `AGENTS.md`, whose `nextjs-agent-rules` block is regenerated by `next dev`
   and cannot be kept clean.
2. **No comments in the codebase.** Write code that does not need them.
3. **Never commit without being asked.** Make the changes, report what changed,
   and wait. This includes staging, branching, amending, and pushing.
4. **No Claude attribution in commits.** No `Co-Authored-By`, no session links,
   no generated-with footers. Commits are authored by Gautam alone.
5. **bun is the package manager.** `bun install`, `bun run <script>`. Never npm,
   pnpm or yarn in this repo.

## The registry

`public/registry` is a build artifact copied from the CLI repo, not source.
`@atarashi/registry` pins `DEFAULT_REGISTRY_URL` to
`atarashi.gautamsuthar.in/registry`, so every published copy of the CLI resolves
blueprints against these files.

Never hand edit anything under `public/registry`. The index carries a root hash
computed over exactly those bytes, and the CLI verifies it. To change the
registry, change the blueprints in the CLI repo, run `pnpm build:index` there,
then `bun run sync:registry` here.

`bun run check:registry` verifies the copy still matches the build hash for hash.

## Scripts

- `bun run dev`, `bun run build`, `bun run start`
- `bun run lint`, `bun run typecheck`
- `bun run sync:registry`, `bun run check:registry`
